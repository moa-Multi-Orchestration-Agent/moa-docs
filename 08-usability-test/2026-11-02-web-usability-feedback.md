## 1. 패널 크기 조절과 접기

영역이 나뉜 화면에서 각 영역의 크기가 고정이고 접을 수도 없는 문제입니다. 창이 좁으면 가운데 작업 영역만 줄어들어 내용이 잘 안 보입니다. 같은 요청을 적용할 화면을 모두 모았습니다.

### 1. 워크플로 편집기 패널

- 화면: 스튜디오 → 워크플로 탭 → 워크플로 열기
- 지금 상태
  - 세 패널 모두 크기가 고정이다. 왼쪽 블록 목록은 폭 220px, 오른쪽 설정은 폭 340px, 아래 실행 로그는 높이 260px이다.
  - 접을 수 있는 건 아래 실행 로그뿐이다. 왼쪽·오른쪽 패널은 닫을 방법이 없다.
- 겪는 문제
  - 캔버스가 좁아져 블록 글자를 읽을 수 없을 만큼 작아진다.
  - 실행 로그 머리글("실행 로그", "노드별 입출력" 등)이 한두 글자씩 줄바꿈되어 세로로 쌓인다.
- 바라는 모습
  - 패널 경계선을 끌어서 폭과 높이를 바꾼다. 최소·최대 크기를 둔다.
  - 왼쪽·오른쪽 패널에 접기 버튼을 두고, 접은 뒤에는 화면 가장자리 버튼으로 다시 연다.
  - 블록을 클릭하면 오른쪽 설정 패널이 자동으로 다시 열린다.
  - 조절한 크기와 접힘 상태는 다음에 열 때도 유지된다.
- 기준: MMI IX-07(오른쪽 패널 폭을 끌어서 360~640px로 조절, 마지막 폭 기억)
- 코드: `features/editor/palette.tsx:39`, `features/editor/editor.tsx:156`, `features/editor/run-console.tsx:63, 77`

## 2. 워크플로 편집기

### 9. 같은 두 블록 사이 연결선이 겹쳐서 어디로 가는지 모른다

- 상황: 한 블록의 출력 두 개(text, json)가 다른 블록의 입력 두 개(질문·지시, 참고 자료)로 이어질 때, 두 선의 세로 구간이 한 줄로 포개진다.
- 원인
  - 연결선을 꺾은선으로 그리고, 꺾는 위치를 두 블록 사이의 한가운데로 계산한다. 그래서 같은 두 블록 사이의 선은 항상 같은 위치에서 꺾인다.
  - 두 블록의 높이가 다르면 세로 구간이 겹친다. 선 색도 모두 같은 회색이다.
- 얼마나 자주 생기나
  - 지금 시드 데이터에서는 공식 템플릿 24개 중 0개, 시드 워크플로 8개 중 2개다.
  - 출력이 두 개인 블록(LLM, RAG 검색)과 입력이 두 개인 블록(LLM)이 흔해서, 사용자가 직접 만들기 시작하면 자주 생긴다.
- 바라는 모습 (손이 적게 드는 순서)
  1. 같은 두 블록 사이의 선마다 꺾는 위치를 10~16px씩 엇갈리게 한다. 포트 순서를 따르면 선끼리 교차하지 않는다.
  2. 선이나 포트에 마우스를 올리거나 블록을 선택하면 해당 선만 진하게 강조하고 나머지는 흐리게 한다.
  3. 데이터 형식(텍스트, 목록, JSON, 이미지)별로 선과 포트 색을 다르게 하고, 마우스를 올리면 "text → 질문·지시" 같은 이름을 보여 준다.
- 코드: `features/editor/canvas.tsx:142`

### 10. 연결이 안 되는 블록끼리 끌면 아무 설명 없이 안 붙는다

- 상황: 블록의 출력 점을 형식이 맞지 않는 입력 점(예: 목록 → 텍스트)으로 끌어 놓는다.
- 지금 상태: 연결선이 그냥 사라지고, 왜 안 되는지 알려 주지 않는다.
- 바라는 모습
  - 끄는 동안 붙일 수 있는 점은 강조하고 안 되는 점은 흐리게 한다.
  - 안 되는 곳에 놓으면 "형식이 맞지 않아요 (목록 → 텍스트)" 말풍선을 띄운다.
  - 말풍선에 "텍스트로 합치기 블록 넣기" 같은 해결 버튼을 둔다.
- 기준: MMI IX-22, 스토리보드 시나리오 4 연결 규칙
- 코드: `features/editor/canvas.tsx:32`

### 11. 블록 옆 '+'로 다음 블록을 바로 붙이기

- 지금 상태: 블록을 추가하려면 매번 왼쪽 목록에서 끌어 오고 연결선도 직접 그려야 한다.
- 바라는 모습: 블록에 마우스를 올리면 오른쪽에 '+' 버튼이 생긴다. 누르면 자주 이어 쓰는 블록 5개가 뜨고, 고르면 오른쪽에 붙으면서 자동으로 연결된다.
- 기준: MMI IX-21, 스토리보드 시나리오 4

### 12. 우클릭 메뉴와 더블클릭으로 이름 바꾸기

- 화면: 워크플로 편집기의 블록, 스튜디오 카드
- 지금 상태: 우클릭이나 더블클릭에 반응하는 곳이 없다. 스튜디오 카드는 '⋯' 버튼으로만 메뉴를 연다.
- 바라는 모습

## 5. 설정 · 예산·사용량

### 16. 알림 비율을 끌어서 설정

- 화면: 설정 → 예산·사용량 탭(워크스페이스 예산, 에이전트별 월 예산 한도)
- 지금 상태
  - 알림 비율은 숫자 입력칸(10~100)만 있다.
  - 워크스페이스 게이지에는 알림 지점 세로선이 있지만 끌 수 없고, 에이전트별 게이지에는 세로선이 없다.
  - 월 한도나 알림 비율을 고쳐도 저장하기 전에는 게이지가 바뀌지 않는다.
- 바라는 모습
  - 게이지 위의 알림 세로선을 직접 끌거나, 게이지 아래 슬라이더로 비율을 정한다. 끄는 동안 "80%" 같은 숫자가 함께 바뀐다.
  - 정확한 값을 넣을 수 있게 숫자 입력칸은 남긴다.
  - 에이전트별 게이지에도 알림 세로선을 보여 준다.
  - 값을 바꾸면 저장 전에도 게이지가 바로 다시 그려진다.
- 기준: MMI IN-14(슬라이더 옆 숫자 표시와 직접 입력, 방향키 ±1, Shift+방향키 ±10), IX-03, SET-01
- 코드: `app/(app)/settings/_components/budget-tab.tsx:42, 89, 102`

### 17. 사용량을 색으로 채워 보여 주기

- 지금 상태
  - 색 채우기 기능은 있다. 평소 파랑, 알림 비율을 넘으면 주황, 한도를 넘으면 빨강이다.
  - 그런데 사용률을 정수 %로 반올림해서 1% 미만이면 폭이 0이 되어 아무것도 안 보인다. 예: $0.11 / $500 = 0.02%.
  - 사용률(%)을 글자로 보여 주지 않고, 금액만 있다.
- 바라는 모습
  - 조금이라도 썼으면 최소한의 폭은 색이 보이게 한다.
  - 사용률을 글자로 함께 보여 준다. 예: "1% 미만", "23%"
  - 색만으로 상태를 구분하지 않도록 알림 비율 초과, 한도 초과를 글자나 아이콘으로도 표시한다(MMI 접근성 기준).
  - 남은 금액도 보여 준다. 예: "$499.89 남음"
- 참고: 목 데이터가 오늘 날짜 기준이라 월초에는 사용액이 거의 0이다. 화면 확인용으로 사용률이 다양한 시드(예: 25%, 85%, 105%)를 넣어 두면 세 가지 색을 모두 확인할 수 있다.
- 코드: `shared/ui/gauge.tsx`

## 6. 여러 화면 공통

### 18. 삭제 확인 창 대신 바로 지우고 '되돌리기' 알림

- 쉽게 말하면: Gmail에서 메일을 지우면 확인 창 없이 바로 지워지고, 화면 아래에 "삭제됨 · 실행취소"가 몇 초 동안 뜬다. 그 방식으로 바꾸자는 제안이다.
- 지금 상태: 스튜디오 카드, MCP 서버, 자격증명 삭제 등 14곳에서 매번 "정말 삭제할까요?" 창이 뜨고 한 번 더 눌러야 한다.
- 바꾸면 좋은 점: 클릭이 한 번 줄고, 실수로 지워도 "되돌리기"로 바로 복구된다.
- 같은 이유로 필요한 곳: 배포·API 목록의 엔드포인트 켜짐 스위치. 지금은 확인도 되돌리기도 없이 한 번 누르면 운영 중인 API가 바로 꺼진다(호출하면 404). "껐습니다 · 되돌리기" 알림이 있으면 좋다.
- 확인 창을 계속 쓸 곳: 결제, API 키 폐기처럼 정말 되돌릴 수 없는 작업
- 기준: MMI 4.3(토스트 "삭제했어요 · 되돌리기"), 3장(되돌릴 수 없는 조작만 한 번 더 확인)
- 코드: `app/(app)/deploy/_components/deploy-view.tsx:38`

### 19. 상단 승인 대기 창에서 내용을 못 본 채 승인된다

- 화면: 상단 오른쪽 "승인 대기 N건" 버튼을 누르면 뜨는 작은 목록 창
- 상황 예시: "AI 뉴스 요약 발송" 워크플로가 메일을 보내기 전에 승인을 기다리고 있다.
- 문제
  - 작은 창의 각 항목에 바로 "승인" 버튼이 있다.
  - 그런데 무슨 내용이 누구에게 발송되는지는 이 창에 보이지 않는다.
  - 실행 상세 화면에는 보낼 내용 미리보기와 "수정 후 승인"이 있는데, 작은 창에서 바로 누르면 이를 건너뛰고 메일이 나간다.
- 바라는 모습: 작은 창 항목에 보낼 내용 1~2줄과 받는 사람을 보여 준다. 또는 작은 창에는 "확인하러 가기"만 두고 승인은 실행 상세에서만 한다.
- 유지할 것: 실행 상세로 이동한 뒤에도 작은 창이 떠 있는 것은 그대로 둔다. 여러 건을 이어서 처리할 때 편하다.
